# Plate Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Plate Log, a phone-first daily exercise log for Nikita's routine. It has a first
visit, set-by-set logging, history, charts and a return experience, and saves to localStorage.

**Architecture:**
- All rules live in pure TypeScript modules in `lib/`, tested with `node --test`:
  - data model, dates, the routine seed, storage, workout operations, stats, validation, sample
    data.
- One client hook (`lib/store-client.ts`) wraps `localStorage` with `useSyncExternalStore`.
  Every write reads the latest saved value first.
- Each route's `page.tsx` is a small server component. It awaits `params` / `searchParams` and
  renders a client screen component from `app/screens/`, which reads the store.
- The look and the shared controls are copied from Assignment 2's Plate Room design system.

**Tech stack:** Next.js 16.3.8 (App Router), React 19.2.8, Tailwind CSS 4, TypeScript 5,
node:test (Node 24 strips the types), next/font/google. No other runtime packages.

**Spec:** `docs/superpowers/specs/2026-10-18-plate-log-design.md`. Read it alongside this plan.
Section numbers like §4.3 refer to it.

## Global constraints

- **Stack:** Next.js 16.3.8, React 19.2.8 and Tailwind 4 only. Add no npm packages (no chart,
  date, state or test libraries).
- **Read the docs first:** read the relevant guide in `node_modules/next/dist/docs/` before writing
  Next-specific code (see `AGENTS.md`). In Next 16, the `params` and `searchParams` page props are
  Promises.
- **Install packages through the IMC mirror:**
  `npm_config_registry=https://imc-npm-proxy.trading.imc.intra/repository/npm-proxy/ NODE_OPTIONS=--use-system-ca`.
  Keep the `package-lock.json` URLs on `https://registry.npmjs.org/`.
- **Builds** need fonts.googleapis.com and fonts.gstatic.com.
- **Storage:**
  - Key `plate-log:v1`.
  - Unreadable data is kept under `plate-log:unreadable-<timestamp>`.
  - Sample data backups go under `plate-log:backup-<timestamp>`.
- **Dates:** a local `YYYY-MM-DD` built from date parts. Never `toISOString()` for a date key.
- **Units:** lb only. Weight 0 means bodyweight. The suggestion step is 5 lb. Targets are 3 sets ×

- **Copy:** error and toast text exactly as in §4 and §7 of the spec. `lib/validation.ts` holds the
  error strings once.
- **Colors:**

  - Arbitrary Tailwind values read `--swatch-*` / `--mood-*`, never `--color-*`.
  - No raw hex or default Tailwind palette classes in components.
- **Accessibility:**
  - Native `button`, `a` and `input` only.
  - Every input has a `<label>` (or `aria-labelledby` to visible text). Errors are tied with
    `aria-describedby`, plus `aria-invalid`.
  - Tap targets are at least 44px.
  - No horizontal scroll at 390px.
- **Imports between `lib/*.ts` files use the `.ts` extension**, and `import type` for types, so
  `node --test` can load them. `tsconfig.json` gets `"allowImportingTsExtensions": true`.

## Review focus

These are inputs the spec implies but doesn't spell out. Each is pinned by a test in the task
named in brackets.
1. **Weight typed as "52.5", " 50 ", "52,5" or "050":** trim it, accept a comma as the decimal
   point, and read it as a number. "5o" is an error. [Task 5]
2. **Logging just before midnight, or across a date change:** the date key comes from the device's
   local date when the save happens, not when the page loaded, and never from UTC. [Task 2]
3. **Two tabs open:** a write in one tab must not erase a newer write from the other. Every
   `update` re-reads storage before applying its change. [Task 6]
4. **Names like "  face   PULLS ", "!!!" or "Lat pulldowns!":**
   - Duplicates are matched after trimming, squashing repeated spaces and ignoring case.
   - A name that turns into an empty slug gets the ID `exercise`.
   - A slug that collides with an existing ID gets `-2`, `-3`, and so on. [Task 3]
5. **localStorage throws on write** (full quota, or private mode partway through a session): keep
   working in memory, report `unavailable`, and never crash the page. [Task 2]

```ts
export function findExercise(store: Store, id: string): Exercise | undefined;
export function exercisesForDay(store: Store, dayId: StrengthDayId): Exercise[];   // store order
export function extraExercises(store: Store): Exercise[];
export function findByName(store: Store, name: string): Exercise | undefined;      // via normalizeName
export function addExercise(store: Store, input: { name: string; dayId: StrengthDayId | "extra" }): { store: Store; exercise: Exercise };

// lib/workouts.ts
export type Removed = { workout: Workout; index: number };
export function findWorkout(store: Store, date: string, dayId: DayId): Workout | undefined;
export function workoutsOn(store: Store, date: string): Workout[];
export function countsAsWorkout(w: Workout): boolean;       // ≥1 logged set or has cardio
export function isLogged(set: SetRow): boolean;             // done && reps ≥ 1 && weight ≥ 0 (non-null)
export function saveEntry(store: Store, a: { date: string; dayId: StrengthDayId; exerciseId: string; sets: SetRow[]; newId: () => string }): Store;
export function finishWorkout(store: Store, workoutId: string, nowIso: string): Store;
export function saveCardio(store: Store, a: { date: string; optionId: CardioOptionId; minutes: number; newId: () => string; nowIso: string }): Store;
export function updateSets(store: Store, workoutId: string, exerciseId: string, sets: SetRow[]): Store;
export function updateCardio(store: Store, workoutId: string, cardio: { optionId: CardioOptionId; minutes: number }): Store;
export function deleteWorkout(store: Store, workoutId: string): { store: Store; removed: Removed | null };
export function restoreWorkout(store: Store, removed: Removed): Store;   // reinserts at index (clamped); no-op if id already present
```
- Every function returns a new `Store` and never mutates its input.
- `saveEntry`:
  - If no workout exists for (date, dayId) and no row in `sets` has `done: true`, it returns
    `store` unchanged (`===`).
  - Otherwise it creates the workout if needed, then replaces or appends that exercise's entry.
- `saveCardio` upserts the (date, "cardio") workout, sets `cardio`, and sets `finishedAt` if it's
  missing.

**Exact outputs to test:**
- **`formatSets`:**
